# Cottonwood Growth Engine — roadmap

Features: lowercase kebab-case slugs, comma-separated. Each becomes `work/briefs/<slug>.md` (`sir plan briefs`) and one `/sir:build`, so one PR. Depends on: earlier phase numbers.

Order follows the spec's priorities: stop losing inbound first, then evidence-backed prospects, then gated outreach. Within a phase, build features left to right; each one merges before the next starts.

| Phase | Goal | Features | Exit criteria | Depends on |
|---|---|---|---|---|
| 1 | Runnable skeleton that every later build is checked with | scaffold | `uv run cottonwood --help` lists the CLI; `pytest`, `ruff check`, `ruff format --check` and `mypy` run from the command line and pass on the skeleton; `cottonwood migrate` creates an empty versioned SQLite file; `/sir:init` re-run picks up the check commands |  |
| 2 | Durable data core and inbound capture (software side of Gate 0) | data-core, inbound-logging | All 7 tables migrate on a fresh database; UPDATE/DELETE on `activities` and DELETE on `suppression` are rejected; `backup` writes a consistent timestamped copy, and the runbook restore procedure restores it; a labeled test form inquiry and test phone inquiry logged with `log-inbound` appear labeled in `review` and are excluded from counts; the duplicate check fires on a same-day match; `docs/runbook.md` has the inbound checklist, relay, restore and deletion-request sections (R-1–R-4, R-31 for review, R-32–R-35) | 1 |
| 3 | Events, stages and an honest report | events-and-stages, weekly-report | `log-event` records every R-15 type and enforces R-14 stages and the R-16 qualification rule; corrections void activities and void activities drop out of counts; `log-time` and `log-cost` record hours and spend; `report --period 7d` and `--period 30d` write Markdown with every R-28 metric, zeros printed and the KPI shown as `n/a` at 0 hours, observed apart from estimated (R-14–R-17, R-28–R-31) | 2 |
| 4 | Evidence-backed prospects (software ready for Gate 1) | prospect-import, prospect-review, research-skill | `prospects-import` accepts valid fixture records, rejects invalid ones naming the record, field and rule, and re-import creates no duplicates; `set-eligibility` refuses without a source or for suppressed addresses; `mark-reviewed` counts feed the report; `review` shows separate candidate queues with checklist, evidence age and the stated order; the `research-prospects` skill produces a file that validates and imports, and its run is recorded with cost and source (R-5–R-13, R-25–R-27) | 3 |
| 5 | Gated outreach loop (software ready for Gate 2) | approvals-and-claims, send-gate, outreach-skill | `approve` refuses without a written-approval reference; claims become `verified` only through a claim approval; `prepare-send` writes a sendable draft only when every R-21 check passes and names each failed check otherwise; `log-outreach` records a send and flags a bypass as a gate violation; `log-reply` opt-out suppresses and bounce makes ineligible in the same command; `suppress` works without a lead; the `prepare-outreach` skill outputs a draft, a claims list and a brief, and skips suppressed contacts (R-18–R-24) | 4 |

**Not on the roadmap:** the founder's open questions and Gate 0–2 business sign-offs. They run alongside the builds and are tracked in `verification.md`. Nothing in the spec's Non-goals gets a phase.
