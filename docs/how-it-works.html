Cottonwood Growth Engine

A local Python CLI, one SQLite file and two Claude Code skills that help Cottonwood Contractors, an early-stage Utah general contractor, capture every inquiry, research commercial prospects with evidence, and send founder-approved outreach that has passed deterministic checks.

Design principle

The one rule

Claude only writes files. The CLI decides what enters the database and what is sendable. The founder approves in writing and sends by hand.

Every other design choice follows from this. The skills have no shell, no database access and no email tool. The CLI makes no network calls. No email-sending credentials exist anywhere in the repo (R-27). An email can only become sendable through prepare-send, and a send that skipped it is recorded as a gate violation.

Trust boundary

Who does what

Claude skills

  • research-prospects searches public professional sources and writes out/research/DATE-SLUG.json
  • prepare-outreach reads one lead export and writes a draft, its claims list and a founder brief
  • Separates verified facts from hypotheses; answers checklist items yes / no / unknown

Cannot: run commands, read the database, see email addresses, send anything. Web text is treated as data, never as instructions.

cottonwood CLI + SQLite

  • Validates research files against a JSON Schema; rejects bad records, never repairs them
  • Deduplicates organizations, contacts and leads on re-import
  • Records approvals, events, sends and replies as append-only activities
  • Runs every send check in prepare-send and writes the only sendable copy
  • Writes the review queue and the weekly report as Markdown

Cannot: reach the network. Operated by the developer on their own Mac.

Founder

  • Gets form notifications and calls; acknowledges inquiries
  • Approves leads, drafts, claims, audiences and offers in writing
  • Sends prepared drafts from Cottonwood's own mailbox
  • Runs remote screens, walkthroughs and proposals
  • Sends the developer a daily note of calls and outcomes

Never runs the CLI. Receives the review, briefs and reports as files.

The developer sits between the lanes: they relay what the founder receives (forwarded Formspark notifications and mailbox replies, the daily call note), run the skills, and run every CLI command, logging everything the same working day.

Lead types and stages · R-14

Three ways a lead enters

Stages are enforced by a CHECK constraint per lead type. A stage moves only through log-event, and every stage change is an activity naming the event that caused it.

Candidate queues in review are ranked by the number of yes checklist answers, ties broken by lower estimated founder time. The checklist items live in config/pilot.yaml: six for direct candidates, five for relationship prospects. No score, no ML.

cottonwood/send.py · R-21

The send gate

prepare-send runs every check and collects every failure before it decides; it never stops at the first one. Passing writes out/send/ID-N.md and a draft_prepared activity. Failing writes nothing sendable and appends a prepare_refused activity listing the checks. The right column shows what would happen today with the current config.

approvalAn unvoided founder approval of the lead, and an approval of a draft whose SHA-256 matches this file byte for byte. Editing an approved draft breaks the match.Per lead
eligibilityThe lead has a contact with an email address, and that contact is eligible. Eligibility needs a public professional source URL (set-eligibility).Per contact
suppressionThe normalized address is not in the suppression table.Per contact
claimsEvery claim in the draft's claims list exists in config/claims.yaml and is verified. A claim becomes verified only through approve claim.All 6 unverified
evidenceThe lead's newest evidence is no older than review.max_evidence_age_days.90 days set
sender_identityThe configured sender name and business appears verbatim in the draft. Empty config refuses every draft.Empty: refuses all
postal_addressA valid business postal address appears verbatim (CAN-SPAM). Empty config refuses every draft.Empty: refuses all
opt_outThe working opt-out line appears word for word.Configured
ad_identificationAd identification appears verbatim when configured; skipped when unset.Configured
$ uv run cottonwood prepare-send 12 out/drafts/12-1.md refused: claims: service-area is unverified refused: sender_identity: not configured (sending.sender_identity is empty) refused: postal_address: not configured (sending.postal_address is empty) # exit 1 · prepare_refused activity recorded · nothing written to out/send/

After the send, log-outreach needs the prepared id. A send with no matching prepared draft, or to an address suppressed since preparation, is still recorded, as a gate_violation that appears in the report.

cottonwood/migrations/*.sql · SQLite

Data model

Seven tables in one file, data/cottonwood.db. Migrations are plain SQL run in order by a small runner that tracks PRAGMA user_version. All times are stored as UTC ISO-8601 and shown in America/Denver.

TableHoldsRules
organizationsFirms, matched on normalized domain, else normalized nameDomain unique where present
contactsPeople: name, email, E.164 phone, role, source URL, eligibilityFields nullable so a deletion request can clear them; row stays
leadsType, stage, segment, channel, checklist, verified facts, hypothesis, value with basis, referred_by, is_testStage CHECK per type; money is exact decimal text with a basis
evidenceURL, observed date, excerpt or observation, fact vs hypothesisNewest observed date drives evidence age
activitiesEvery write: inquiries, imports, approvals, events, sends, replies, refusals, correctionsAppend-only. Triggers block UPDATE, DELETE and REPLACE. A correction is a new row that voids an old one; voided rows drop out of all counts. The one exception: a deletion request removes the person's details from their payloads and logs that it did
agent_runsEach skill run: version, model, times, input/output, validation, tokens, cost and its sourceCost marked estimated when not exact
suppressionOpted-out or deleted addresses, keyed on normalized emailNever changed or deleted. Re-inserting an address is silently ignored, so the original row stays

Suppression is checked in four places: prospects-import (matches import as ineligible), set-eligibility, the lead export the drafting skill reads (draftable: false), and prepare-send.

cottonwood report · R-28

The weekly report

The developer sends it to the founder each week. It counts what actually happened in the period, prints zeros as 0, keeps observed outcomes apart from founder estimates, and leaves out test inquiries and voided activities.

Month-one KPI
KPI = qualified direct conversations + partner conversationsfounder hours

Qualified direct conversations are leads entering buyer_need_confirmed; partner conversations are partner_conversation events. The KPI shows n/a when hours are 0. It is measured, not promised: zero is a valid result.

Also reported: inquiries by channel and segment, same-working-day acknowledgements, missed and returned calls, hand-review counts per motion, approvals, prepared drafts, sends, gate violations, replies by type, screens, walkthroughs, proposals, wins, referrals, founder hours, model cost against the optional monthly cap, other costs, opt-outs, data-quality failures, and the open question blocking sending when one is configured.

Spec constraints and gates

Guardrails

Founder gates before volume

  • G0 Truth: inbound checklist complete; form, phone and relay verified
  • G1 Evidence: at least 5 hand-reviewed per motion, 0 fabricated
  • G2 Contact: every “before first send” question answered, claims verified, sender identity and postal address set, restore rehearsed
  • G3 Repeatability: two weekly reports in a row with 0 gate violations and same-day opt-outs

Deliberately out of scope

  • Automated or scheduled steps, and programmatic email sending
  • Formspark API, webhooks or export imports
  • Scraping behind logins or permit portals; bought data
  • Scores, ML, dashboards, a CRM or a web UI
  • Blocking Claude runs automatically; cost caps are record-only
  • Presenting prior-employer projects as Cottonwood's own work
